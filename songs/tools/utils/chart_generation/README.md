# Musirail chart generator

The shared entry point analyzes a song once and writes a deterministic
`chart.json` containing Easy, Normal, and Hard interpretations of one shared
musical event map.

From the project root:

```bash
.venv/bin/pip install -r songs/tools/utils/requirements.txt
.venv/bin/python songs/tools/ogg2json.py /path/to/song-directory
```

The generator now produces:

- BPM confidence, half/double-tempo alternatives, downbeats, measures, local
  tempo regions, silence/low-energy regions, and raw onset-to-grid offsets;
- coarse intro/verse/buildup/chorus/break/outro sections and repeated phrase
  families from energy, percussion, chroma, and spectral changes;
- stable alternating, run, mirrored, sweep, center-out, and syncopated motifs;
- nested difficulties selected from the same interpreted events;
- holds from sustained harmonic evidence, slides from pitch movement, flicks
  from accents/transitions, chords from simultaneous band evidence, and release
  tails from detected cutoffs;
- automatic repair for spacing, movement speed, sustain conflicts, slide
  crossings, chord widths, silence, density, and the end of the song.

Every run also writes `analysis_report.json` and `quality_report.json`. The
first exposes the timing and structure evidence for human review. The second
contains density, gesture counts, releases, chord counts, maximum movement
speed, detected conflicts, repairs, section coverage, pattern usage, and
difficulty relationships. All presets are generated by default:

```bash
.venv/bin/python songs/tools/ogg2json.py /path/to/song-directory
```

Use `--difficulty` to produce a smaller chart containing only one preset, or
`--difficulties` to choose a subset:

```bash
.venv/bin/python songs/tools/ogg2json.py /path/to/song-directory --difficulty hard
.venv/bin/python songs/tools/ogg2json.py /path/to/song-directory --difficulties easy normal
```

Use `--output chart-preview.json` to inspect a result without replacing the
active chart. Use `--no-reports` when reports are not wanted. Relative audio,
chart, and report paths are resolved from the song folder. Reusing the same
audio, timing overrides, and seed produces the same charts.

### Manual timing overrides

A trustworthy grid matters more than complex gestures. Add reviewed values to
the song's `metadata.json` when automatic timing is wrong:

```json
{
  "title": "Example",
  "audio": "audio.ogg",
  "chart": "chart.json",
  "timing": {
    "bpm": 161.5,
    "first_beat": 0.72,
    "time_signature": 4
  }
}
```

The same values can be tested without editing metadata:

```bash
.venv/bin/python songs/tools/ogg2json.py /path/to/song-directory \
  --bpm 161.5 --first-beat 0.72 --time-signature 4 \
  --output chart-preview.json
```

The app scans song directories in `user://songs` at runtime, so generated
tracks do not need a source-tree catalog. Import the finished directory or
share it as a `.musirail` package through the app.

Version 4 stores shared song timing once and nests playable notes by
difficulty:

```json
{
  "version": 4,
  "timing": {"bpm": 120.0, "first_beat": 0.16},
  "difficulties": {
    "easy": {"label": "Easy", "stars": 1, "notes": []},
    "normal": {"label": "Normal", "stars": 3, "notes": []},
    "hard": {"label": "Hard", "stars": 5, "notes": []}
  }
}
```

Slides use a timed path. `interpolation` accepts `linear` or `smooth`, and
`release_required` makes releasing near the last point part of the gesture:

```json
{
  "type": "slide",
  "path": [
    {"time": 12.0, "x": 0.2},
    {"time": 12.4, "x": 0.8},
    {"time": 12.8, "x": 0.35},
    {"time": 13.2, "x": 0.65}
  ],
  "width": 0.18,
  "interpolation": "smooth",
  "release_required": true
}
```

`path` and `release_required` are mandatory for slides. `release_required` is
also mandatory for holds. When it is true, releasing too early or continuing
to hold after the late window produces a MISS. A valid release is judged
independently, and the note keeps the worse of its press and release judgments.
